---
title: GraphQL
description: GraphQL API for querying and mutating MockForge data with a typed schema.
---

MockForge provides a GraphQL API with the same 14 entities as the REST API. Send `POST` requests with a JSON body `{ "query": "...", "variables": { ... } }`. Mutations use the same generator + shallow-merge semantics as REST `POST` / `PUT` and do not persist.

## Endpoint

| Environment | URL |
| ----------- | --- |
| Production | `POST https://api.mockforge.dev/graphql` |
| Local dev | `POST http://localhost:4000/graphql` |

## Playground

| Tool | URL |
| ---- | --- |
| **GraphiQL** (API server) | Open `http://localhost:4000/graphql` in a browser while the API is running — GraphiQL is enabled on `GET` / `POST` at that path. Production: `https://api.mockforge.dev/graphql`. |
| **In-app playground** | [`/playground`](/playground) on the web app — GraphQL tab with presets for queries and mutations. |

## Query structure

List fields return arrays directly (not wrapped in a `data` envelope). Pagination args:

- `limit` — number of items (default: 10, max: 100)
- `skip` — offset (default: 0)
- `search` — filter string where supported

## Example queries

### Users

```graphql
query GetUsers {
  users(limit: 5, skip: 0) {
    id
    firstName
    lastName
    email
    phone
  }
}
```

### Products

```graphql
query GetProducts {
  products(limit: 10) {
    id
    title
    description
    price
    category
  }
}
```

### Stocks with search

```graphql
query SearchStocks {
  stocks(search: "AAPL", limit: 5) {
    id
    symbol
    name
    price
    change
    changePercent
  }
}
```

## Query root

- `users`, `products`, `posts`, `comments`, `todos`, `carts`
- `messages`, `notifications`, `quotes`, `recipes`, `countries`, `companies`, `stocks`, `events`

Singular lookups: `user(id)`, `product(id)`, `post(id)`, … (same pattern for each entity).

## Mutations

Naming: `create*`, `update*`, `delete*` in camelCase (e.g. `createUser`, `updateProduct`, `deleteTodo`).

- **Create / update** — optional scalar args are shallow-merged onto one generated row (same as REST body merge). Nested objects (e.g. cart `products`, recipe `ingredients`) are not overridable via separate GraphQL input types in this version; only top-level scalar fields on the mutation args apply.
- **Delete** — returns `DeleteResult { deleted, id }`, matching REST `{ "deleted": true, "id": "..." }`.

Existing demo mutations remain available: `createPost`, `updateTodo`.

### Examples

```graphql
mutation CreateUser {
  createUser(firstName: "Ada", email: "ada@example.com") {
    id
    firstName
    email
  }
}
```

```graphql
mutation UpdateProduct {
  updateProduct(id: "1", title: "Custom title") {
    id
    title
    price
  }
}
```

```graphql
mutation DeleteTodo {
  deleteTodo(id: "todo-1") {
    deleted
    id
  }
}
```

All 14 standard resources (excluding `/rest/custom`) expose create, update, and delete where REST does.

## Headers

Include `X-MF-ID` for identity-scoped rate limiting:

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "X-MF-ID: your-custom-id" \
  -d '{"query":"{ users(limit: 5) { id firstName } }"}' \
  http://localhost:4000/graphql
```
