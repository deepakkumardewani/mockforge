All built-in resources live at `/api/{entity}` on this origin. Data is generated per request.

<DocsBaseUrl path="/api/{entity}" />

## Query parameters

| Parameter | Default | Notes                              |
| --------- | ------- | ---------------------------------- |
| `limit`   | `30`    | 1–100                              |
| `skip`    | `0`     | Offset                             |
| `search`  | —       | Substring filter on list endpoints |

`sort` and `order` are accepted but unused.

## List envelope

```json
{
  "data": [{ "id": 1 }],
  "total": 100,
  "limit": 30,
  "skip": 0,
  "meta": {
    "entity": "users",
    "generatedAt": "2026-09-13T14:30:00.000Z"
  }
}
```

## Single item

`GET /api/{entity}/:id` returns `{ "data": { ... } }`. The `:id` is a **1-based offset** into the generated set, not a stored primary key.

## Search

Dedicated search (same envelope):

<DocsCurlList paths={["/api/users/search?q=john"]} />

List endpoints also accept `?search=`.

## Writes do not persist

`POST`, `PUT`, and `DELETE` return a mock result. The next list call will not include them.

- `POST /api/{entity}` → `{ data }` (201), body fields shallow-merged onto a generated row
- `PUT /api/{entity}/:id` → `{ data }`
- `DELETE /api/{entity}/:id` → `{ "deleted": true, "id": "..." }`

## Errors

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Human-readable error message"
  }
}
```

| Code                    | Status | When              |
| ----------------------- | ------ | ----------------- |
| `INVALID_QUERY`         | 400    | Bad query params  |
| `NOT_FOUND`             | 404    | Missing resource  |
| `TOO_MANY_REQUESTS`     | 429    | Over the rate cap |
| `INTERNAL_SERVER_ERROR` | 500    | Server failure    |

Quotas: [Identity & rate limits](/docs/identity).
