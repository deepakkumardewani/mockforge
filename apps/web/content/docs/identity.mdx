---
title: Identity & rate limits
description: One browser UUID owns your schemas and, if you send it, raises the request quota.
---

MockForge has no accounts. A browser UUID (`mf_id`) does two jobs:

1. **Owns schema definitions** in the builder (`POST` / `GET` / `PUT` / `DELETE` `/api/schemas`)
2. **Raises the HTTP quota** when you send it as `X-MF-ID`

Public sample data (`GET /api/{entity}`, `GET /api/custom/{slug}`, GraphQL) works without it.

| You send              | Quota       |
| --------------------- | ----------- |
| `X-MF-ID` header      | 300 req/min |
| Nothing (IP fallback) | 60 req/min  |

The limiter is a **fixed 60-second Redis window** keyed on that id (or an IP hash). Missing Redis fails open and may omit headers.

## Recovery key (builder)

On first visit to the [builder](/builder):

1. The browser stores `crypto.randomUUID()` in `localStorage` as `mf_id`
2. Schema-management calls send it as `X-MF-ID`

Copy the key and use **Restore** on another device (or after clearing storage). Restore accepts a UUID only. The API accepts any non-empty `X-MF-ID` for quotas.

The second call is public. Management verbs and ownership details: [Custom schemas](/docs/custom-schemas).

## Response headers

When the limiter runs, responses include:

| Header                  | Meaning                        |
| ----------------------- | ------------------------------ |
| `X-RateLimit-Limit`     | Cap for this window            |
| `X-RateLimit-Remaining` | Requests left                  |
| `X-RateLimit-Reset`     | Unix time when the window ends |

Over the cap:

```json
{
  "error": {
    "code": "TOO_MANY_REQUESTS",
    "message": "Rate limit exceeded"
  }
}
```

`Retry-After` is `60` seconds. Playground and GraphQL attach `X-MF-ID` automatically so they share the higher cap.
